# 音乐踩点

先收音乐，再排画面。换歌必须重新分析、排片，不能只换模板的 BPM。

```bash
python scripts/analyze_music.py work/song.wav --out work/music --target-seconds 30
```

接受音频或带声音的视频，输出 `beatmap.json`、`report.md`、`structure.png`。默认最多分析前 600 秒，可用 `--max-seconds` 调整；长歌的推荐窗口只在已分析范围内寻找，不代表扫描了未解码的后半首。

## 用耳朵理解结构

- **intro 前奏**：主段开始前的铺垫。听每一下明显的「咚」，开头在这些时刻换脸、风格或大字；声音停下时，让问题句和光标安静地留着。
- **drop 落点**：从收着的声音突然打开的那一下，适合让人物走进来。脚本比较前后响度并要求响声持续，避免把单次鼓击当成 drop；不明显时是 `null`，不用硬造。没有前奏时，排片器借前两小节做开头。
- **乐句 phrases**：音乐里一个听起来完整的小段，像一句话。默认 8 拍一组；120 BPM 大约四秒，86 BPM 就更长。
- **swell 铺垫**：一句话的前半，动作完整地走；**chop 碎拍**：最响、鼓最密的地方，把同一动作切成几刀；**breath 呼吸**：声音收住，给一个安静但仍在动的镜头，或者九格回顾。
- **climax 高潮**：平均响度最大的乐句。变化后的造型从它后面的第一句揭开。**ending_hit** 是靠近结尾的最后一个强拍，适合炸成一个词。

这不是自动读懂编曲。检测不清时，乐句按前半铺垫、接着四分之一碎切、最后四分之一呼吸分配，`confidence:0.25`、`method:"fallback 2:1:1"` 明确标出。排片时这些边界还会吸附到实际拍点。

## JSON 和结构图

| 字段 | 内容 |
|---|---|
| bpm / detected_bpm | 排片速度 / 原始估计速度；倍速歧义优先让一拍长 0.35–0.75 秒，同时保留 60–180 BPM 范围 |
| beats / bars | 逐拍秒数 / 估计小节线；拍号不保证正确 |
| energy | 每 0.25 秒一项 `{time,rms,db}`，末项可不足 0.25 秒 |
| hits / silences | 候选瞬态及强度 / 至少 0.12 秒的低响度空隙；不是所有瞬态都算开头的重击 |
| drop | 最明显的持续能量跃升时刻；无可靠候选为 null |
| intro | start、end、按强度排序的 hits、gaps |
| phrases | start、end、energy、confidence、method，以及 swell/chop/breath 三个时间范围；suggested_edit 是兼容旧工具的同义数组 |
| climax | 最响乐句的 id、start、end、energy |
| ending_hit | 最后一个适合结尾的强拍秒数 |
| window | 推荐 start/end，起点在估计小节线，尽量兼顾前奏、drop、高潮 |

图上有重击、响度曲线、拍线、小节线、前奏空隙、三段乐句、高潮、结尾强拍和推荐窗口。报告解释速度选择和拍号限制。

自动检测比较三拍/四拍的重音周期及三连细分；证据不足默认 4/4，并提示 3/4 与 6/8 可能混淆。试听后用 `--meter 3/4`（默认每句 6 拍）或 `--meter 6/8`（以附点四分音符为一编辑拍，每小节 2 拍、每句默认 4 拍）覆盖。用 `--phrase-beats N` 配句长；默认值 8 会按上述拍号适配。BPM 指编辑拍，不能混用六个八分音符与两个附点四分音符。

## 检测错了怎么改

1. 先听原音乐，并对照结构图；所有 JSON 时间都是**原音乐绝对秒数**。
2. drop 错了：改 `drop` 和 `intro.end`，筛选 intro.hits / gaps；同时按新的落点重分 `phrases`，不要只改一个数字让乐句还停在旧位置。
3. 碎切或呼吸位置错了：改对应乐句的 `swell` / `chop` / `breath`，保持三段连续覆盖该句；同步 `suggested_edit`，写下人工修正和置信度。
4. 高潮错了：改 `climax`；没有后续乐句就不能在这个窗口完成反转。选择更长窗口或另一处窗口，排片器会给提示。
5. 速度翻倍：从相邻拍中取一半，或重新运行指定拍号的分析；修改 bpm 时也必须改 beats / bars / phrases，单改数字不会移动已有拍点。
6. 窗口不满意：直接改 `window.start/end`；或在 style.json 设 `target_seconds` 重新推荐。先试听窗口开头和结尾，再运行 plan.py。

正片在真实拍点和四分之一拍上切，开头在实际重击/空隙边界上切。帧率量化通常半帧，快切组合舍入允许一帧内；最终以实际成片和拼板验证。窗口末端按目标时长量化，不强称它一定是整拍。

用户明确要延长时，仍可用 assemble 的旧版插拍入口：`--insert-at 4 --insert-beats 2 --beatmap work/music/beatmap.json`。画面和完整拍块同时延长；不要把默认排片改成补帧慢动作。
