# 踩坑

- 镜像会让「左脸」变成画面右边。先看举手测试，用用户身体的左右沟通。
- 人脸额外放大容易失真、显疲惫。默认只做一次固定 9:16 裁切，不追着脸推近。x 偏移整段固定，取值是源画宽度比例。
- 逐帧人脸对齐让背景、肩膀漂移，看起来像生成视频。只跟踪叠加图形，不变换视频。
- 补帧慢动作会让手与刀的边缘变假。源帧率转换使用 ffmpeg `fps` 的丢/重复采样，不做光流插值；不要把这种采样称为生成补帧。
- 风格图需要进退场和呼吸。除重击短闪外，用 `transition_frames:4` 等方式进出，真实视频继续走。避免连续整秒密集闪烁；安排 ≥1 秒可看清的镜头。
- 漂白银盐容易显老，最终改用 M3。原片不套整体滤镜。
- 正脸做 1-bit 容易眼鼻糊成一团；先试侧脸。字符图缩小后可能看不清，调整 cell，最终用实际手机尺寸审。
- 白底发黄常因 RGB→YUV 矩阵、范围和标记不一致。编码使用 `scale=in_range=pc:out_color_matrix=bt709:out_range=tv:flags=accurate_rnd+full_chroma_int`，配 `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv -pix_fmt yuv420p`。解码复核也需显式按 BT.709 转回 RGB。纯白应接近 255/255/255，纸底本来就是暖色，不能把纸底当白色错误。
- 内存小就逐帧读、逐帧写 ffmpeg，不用 capture_output 把整段 rawvideo 放内存。九格只保存当前帧与蒙版，内存随输出分辨率、同时解码器数增加，不随整片长度增长。先做低分辨率小样，最终分段渲染。
- HEVC、手机旋转与可变帧率交给 ffmpeg 解码；`-ss` 在输入前只读取所需窗口。素材不足会明确报错，不循环、不拿末帧补长。
- Outfit 只覆盖拉丁字形。HTML 中文用系统字体；片中文字需要中文时显式提供有授权的字体，不复制系统商业字体进仓库。
- 所有样张、源路径映射、音乐、渲染与日志只在私有目录。发布前检查 Git 实际跟踪文件，不能只相信忽略规则。
